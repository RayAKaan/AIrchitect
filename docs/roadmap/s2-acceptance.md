# S2 Acceptance Contract

S2 now has executable deterministic contracts for the backend pipeline:

`brief → requirements → program → envelope → concept strategies`

## Verified in tests

- brief normalization and content identity;
- requirement extraction with explicit missing information and contradiction reporting;
- requirement persistence/confirmation boundaries;
- deterministic architectural program space/adjacency structure;
- metric local projection for setback geometry;
- explicit UNKNOWN planning inputs rather than fabricated rules;
- deterministic envelope hashes;
- three distinct concept strategy families: balanced, compact, low-rise;
- concept generation requires current program and envelope artifacts;
- concept alternatives expose metrics, constraints, assumptions, unknowns, trade-offs, and provenance.

## Stage boundary

S2 establishes the authoritative computational contract. It does not claim construction-ready geometry, code certification, a universal command language, IFC round-trip, or production collaboration.

The existing deterministic design engine remains the geometry/massing execution authority. S2 wraps it with program/envelope prerequisites and provenance rather than introducing a second concept engine.
